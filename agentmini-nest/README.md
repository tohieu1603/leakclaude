# AgentMini-Nest

Minimal NestJS-based AI agent server with tool calling, session persistence, and context compaction.

## Quick start

```bash
# 1. Install
npm install

# 2. Configure
cp .env.example .env
# fill AI_API_KEY, AI_API_URL, AI_MODEL

# 3. Run (hot reload)
npm run dev

# Or production
npm run build && npm start
```

## Features

- 12 Claude-Code-style tools: `Bash`, `Read`, `Write`, `Edit`, `MultiEdit`, `Glob`, `Grep`, `LS`, `WebFetch`, `WebSearch`, `TodoWrite`, `Sleep`
- 8 slash commands: `/help`, `/clear`, `/compact`, `/cost`, `/model`, `/tools`, `/resume`, `/export`
- Async-generator agent loop with retry, parallel tool execution, and end-to-end abort
- Auto + manual context compaction (171K-token threshold, two levels)
- JSONL session persistence — resume across restarts
- Per-client session map — multi-turn `curl` without manually threading `sessionId`
- Server-Sent Events streaming
- Opt-in API-key auth + rate limiting

## Endpoints

```
POST   /api/chat               SSE stream
GET    /api/chat/stats         server status
GET    /api/chat/sessions      list persisted sessions
DELETE /api/chat/:sessionId    remove session
```

## Auth

Set `API_KEYS=key1,key2` in `.env` to enable. Clients send either header:

```
Authorization: Bearer <key>
X-API-Key: <key>
```

When `API_KEYS` is empty/unset, auth is **OFF** (dev mode).

## MCP integration

Drop a `.mcp.json` next to `package.json` to attach external MCP servers. Tools they expose are auto-registered at startup with names prefixed by the server name (e.g. `filesystem__list_directory`).

```bash
cp .mcp.json.example .mcp.json
# edit paths/keys as needed
npm run dev
```

Verify: the boot log shows `Dynamically registered tool: <server>__<name>` for each tool, and `/api/chat/stats` lists them all.

A single failing server is isolated — other servers still come up; the bad one is logged and skipped. On shutdown (SIGTERM/SIGINT) all child processes are cleaned up.

Supported transport: **stdio** (spawn child process). SSE (remote MCP) is planned for Phase 2.

## Rate limit

Defaults: 30 requests / 60 s per IP. Override with `RATE_LIMIT_TTL_MS` and `RATE_LIMIT_MAX`. Disable with `RATE_LIMIT_DISABLED=1`.

## Example

```bash
# Without auth
curl -N -X POST http://localhost:3000/api/chat \
  -H 'Content-Type: application/json' \
  -d '{"message":"Count .ts files in src"}'

# With auth
curl -N -X POST http://localhost:3000/api/chat \
  -H 'X-API-Key: my-secret-key' \
  -H 'Content-Type: application/json' \
  -d '{"message":"Count .ts files in src"}'
```

## CLI helper

```bash
export PATH="$PWD/bin:$PATH"
export AGENTMINI_KEY=my-secret-key   # only when auth is on

agentmini "Create demo.csv with 5 sample rows"
agentmini "Add a Status column"        # auto-continues the same session
agentmini --list
agentmini --stats
```

## Architecture

See [docs/project-report-vi.docx](docs/project-report-vi.docx) chapter 5 or `scripts/diagrams.py` for the architectural diagrams.

Layered design: interface (ChatController, ClientSessionMap, CommandRegistry) → orchestration (QueryService, AiService, CompactionService, ToolRegistry) → storage (SessionService, SessionStore, TodoStore) → tool implementations + external services.
